# Fund Sales AI CRM · 公募基金销售客户维护助手

一个面向**个人/机构客户、机构多联系人、客户需求、拜访纪要、回访任务、口述持仓、市场风险/机会提醒**的多租户 CRM 研发起点。

> **定位**：可运行的参考后端 + 简单 Web 聊天工作台 + Markdown 架构方案 + 测试。它**不是**已通过金融合规/安全验收的生产系统，也**没有接入实时行情、真实基金交易或向客户自动发送消息**。仓库中的客户和市场案例均是虚构数据。

## 功能速览

- 一个机构客户有多个联系人，个人客户独立管理。
- 客户/联系人/需求/拜访/持仓陈述/回访任务存储于关系数据库，长文本使用 Markdown。
- 自然语言：`今天拜访了王敏，需求：关注红利策略；30天后回访`。
- **先返回预览**，确认后在单事务中写入；重复确认不重复建档。
- `本周谁需要跟进` 等结构化只读查询。
- 每 30 天周期回访、完成旧任务后产生下一期任务、到期提醒去重。
- 人工录入市场主题事件后，按租户+销售私有范围匹配已申报持仓/开放需求，产生可解释的**站内服务提醒**。
- PostgreSQL RLS + API 级双过滤 + 复合外键，默认不同租户/不同销售互不可见。
- 实验性网页：`/`；Swagger API：`/docs`。

## 本地 5 步运行（只用合成数据）

```bash
cd fund-crm-assistant
python -m venv .venv
source .venv/bin/activate
python -m pip install -e ".[test]"
cp .env.example .env
alembic upgrade head
uvicorn app.main:app --reload
```

打开 `http://127.0.0.1:8000/docs`，首先调用仅开发环境启用的 `POST /auth/dev-register-tenant` 注册演示租户，再访问 `http://127.0.0.1:8000/` 登录聊天界面。

通过脚本完成完整虚构演示（API 必须先启动）：

```bash
python -m scripts.demo_flow
```

跑单元测试：
```bash
pytest -q
```

## PostgreSQL 容器

`docker-compose.yml` 是**本机开发/集成环境示例**。使用它之前请设置强随机 `JWT_SECRET_KEY`；迁移容器使用 owner 权限，API 使用 RLS 受限角色。详见部署文档的身份初始化步骤与安全注意事项。

## 明确的不包含项

- 不自动发送短信/企微/邮件，也没有常驻 cron worker（到期站内提醒需登录或调用 reconcile）。
- 没有真实市场数据供应商；全部事件需受控人工导入，示例是虚构事件。
- 不做交易、基金推荐决策、基金适当性匹配、收益预测。
- 不做持仓账户核验；所有手工输入的“买了/持有”默认 `verified=false`。
- 当前 LLM 接口默认关闭，离线规则只覆盖部分可验证的中文句式。
- 不包含企业级 SSO/MFA、字段级加密、已审批的外部模型使用、客户资料共享审批、生产灾备/不可变审计。

## 架构的核心原则

**SQL 是事实与权限，Markdown 是记忆与解释，AI 是有确认门槛的翻译器，市场规则只负责提醒人工复核。**
